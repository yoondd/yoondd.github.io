우리집 금고를 거실에 두고 누구나 열 수 있도록 허용한 것과 같다.

1. 공개 메서드에 값 변경 금지
2. 변경해야한다면 검증 절차 추가
3. 민감한 변수는 외부에서 바로 읽기/쓰기 차단

위와 같은 방법으로 해결할 수 있다.

## 문제상황

``` java
class BankAccount {
    private int balance = 0; // 중요한 변수

    // 위험: 외부에서 잔액을 '아무 값'으로 바꿀 수 있음
    public void setBalance(int newBalance) {
        balance = newBalance; // 검증 없이 바로 변경
    }

    public int getBalance() {
        return balance;
    }
}
```

```java
public class Test {
    public static void main(String[] args) {
        BankAccount account = new BankAccount();
        account.setBalance(1_000_000); // 마음대로 돈 넣기 가능
        account.setBalance(-999999);   // 음수 잔액도 가능 (보안 취약)
        System.out.println(account.getBalance());
    }
}
```

- `setBalance()` 메서드가 _아무 검증 없이_ 중요한 변수 `balance`를 바꾼다 
- 외부에서 악의적인 값(음수, 너무 큰 값 등)을 넣을 수 있음.
- 금고를 누구나 열어 직접 내용물을 바꾸는 것과 같음.

## 개선된버전

```java
class BankAccount {
    private int balance = 0;

    // 안전: 직접 설정 대신 "입금" / "출금" 메서드 제공
    public void deposit(int amount) {
        if (amount > 0) {
            balance += amount;
        } else {
            throw new IllegalArgumentException("입금액은 0보다 커야 합니다.");
        }
    }

    public void withdraw(int amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
        } else {
            throw new IllegalArgumentException("출금액이 잘못되었거나 잔액 부족");
        }
    }

    public int getBalance() {
        return balance;
    }
}

```

```java
public class Test {
    public static void main(String[] args) {
        BankAccount account = new BankAccount();
        account.deposit(1000);   // 올바른 방법
        account.withdraw(500);   // 잔액 내에서 출금
        System.out.println(account.getBalance()); // 500
    }
}

```

1. `setBalance` 같은 무제한 변경 메서드 제거
2. 데이터를 바꿀 때는 **검증 로직**을 거치도록 함
3. 외부에서는 변수 내용을 읽기만 가능, 수정은 안전한 메서드로만 가능
